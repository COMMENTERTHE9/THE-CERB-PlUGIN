## Confirmed open issues (current)

### 1. Uncommitted fix work — HIGHEST PRIORITY
99 modified + 18 new files in the working tree, +1,719 / −2,847 vs `HEAD`. This includes essentially all the P0/High fixes above, the removal of the region/protection system, and new files (`HealthLifecycleEngine`, `ChunkDiscoveryManager`, `DamageResolution`, `CerbTabCompleter`, a first unit test). **None of it is committed.** Commit it before doing anything else.

### 2. Repo hygiene
- **`Creb/` is an accidental nested git repository** — a full duplicate of the project tree (with its own `.git`, and even a `Creb/` inside `Creb/`). The parent tracks it as a gitlink (`160000`) with no `.gitmodules`, so `git status` shows perpetual "modified: Creb (new commits)" noise. It should almost certainly be deleted.
- **`target/` is still tracked** despite being in `.gitignore` (committed before the ignore rule). `git rm -r --cached target dependency-reduced-pom.xml` will stop the churn.

### 3. First Aid landmine (dead, but dangerous)
`FirstAidSkill.applyEffect()` grants `level*1500` max HP + `level*1000` regen + `(level-100)*3000` above L100. At L100 that's +150,000 HP. It is currently never called, but if someone wires it up later it instantly breaks combat. Either delete the class or rewrite onto `ScalingFormula` with a hard cap while it's fresh.

### 4. Stale documentation (actively misleading)
- `AI_HANDOFF.md` — says "January 2025", "Paper 1.21.1", "DecentHolograms"; all superseded by the Folia migration. Contradicts reality.
- `CLAUDE.md` — still lists Paper 1.21.1, region management, "database tables not created on startup" (the tables *are* created now).
- The three `audit/*.md` reports are now partly stale (this doc supersedes them for status).

### 5. `--enable-preview` fragility
The shaded jar is pinned to **exactly** JDK 21 — it will refuse to load on any other Java major version, and preview APIs can change between releases. Worth confirming any preview feature is actually needed; if not, dropping it removes a whole class of runtime/build pain.

### 6. Gameplay gap: mob progression
Player damage/skills scale hard, but custom mobs mostly use vanilla or hardcoded HP and `resolveMobLevel()` does not yet derive tier/level HP from `mobs.yml`. This is the main "the game isn't balanced yet" lever, not a bug.

### 7. Known skill stubs (mostly intentional)
DefensiveMagic disabled (no Folia input system after ProtocolLib removal), Trading deferred (needs NPC/market systems), AnimalTaming has empty helper methods, Scavenging chest-detection is a known-broken placeholder.

## What's genuinely working

- Compiles under JDK 21; health-lifecycle engine has unit tests that pass.
- Folia threading looks correct: async tasks do DB I/O only; results are handed back to the entity thread via `player.getScheduler()`. No Bukkit player/entity calls found on async threads.
- All 5 DB tables (`player_custom_ids`, `player_skills`, `skill_effects`, `player_magic_find`, `visited_chunks`) are created on startup and every read/write is covered.
- Per-player state for skills, mana, and virtual health is now UUID-keyed.
- Session lifecycle is centralized in `PlayerSessionManager` with generation-based stale-callback detection.

2. **Repo hygiene**: delete `Creb/`, untrack `target/` + `dependency-reduced-pom.xml`, confirm `.gitignore` covers them.
